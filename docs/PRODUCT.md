# 考研学习中控台：产品档案

## 产品定位

考研学习中控台是一套“个人自用 Beta”学习操作系统，把计划、执行、背诵、错题和复盘放在同一工作区，并通过可迁移的本地数据文件维持长期连续性。它优先解决个人备考过程中的信息分散和复盘断层，而不是提供课程内容或多人协作。

## 目标用户与核心问题

目标用户是需要长期独立备考、愿意维护结构化记录并能自行部署工具的考研学生。核心问题包括：

- 每日任务与阶段规划散落，难以从长期目标落到当天行动。
- 背诵和错题需要多轮回看，普通清单无法保留复盘上下文。
- AI 整理结果与原始学习档案分离，不利于继续编辑和追踪。
- 个人学习数据需要可控、可备份、可迁移，而不是锁在第三方平台中。

## 主要使用流程

1. 在规划区拆解阶段目标，形成每日任务和背诵任务。
2. 学习过程中更新任务进度，录入错题和反思材料。
3. 使用文本 AI 整理错题、编辑表述或进行针对性问答。
4. 使用图像 AI 或本地渲染生成可复习的彩色笔记。
5. 在报告与历史记录中复盘，再调整后续计划。
6. 出现误操作时从自动备份恢复上一版本。

## 功能矩阵

| 领域 | 当前能力 | 数据归属 |
| --- | --- | --- |
| 每日执行 | 每日任务、状态维护、进度记录 | `state.json` |
| 英语阅读 | 传统阅读 A 节成绩趋势、Text 强弱、错因、全文、词库与动态复习 | `state.json` |
| 背诵复习 | 背诵任务与复习内容管理 | `state.json` |
| 错题复盘 | 录入、AI 整理、编辑、问答、后台任务 | 最终内容在 `state.json`，队列仅在本机 |
| 阶段规划 | 规划项目、目标和关联行动 | `state.json` |
| 反思报告 | 反思记录与阶段报告 | `state.json` |
| 笔记生成 | 图像生成、本地渲染与静态图片访问 | `generated-notes/` |
| 历史恢复 | 自动备份、列表与版本恢复 | `backups/` |
| 外部集成 | 第三方错题集合连接和资源缓存 | 凭据与缓存仅在本机 |
| 系统设置 | AI 提供商、监听参数和访问 token | `.env`，不入库 |

## 信息架构

- 主控制台：总览、每日行动和各学习模块的统一入口。
- 规划与任务：长期规划、每日任务、背诵任务。
- 错题与复盘：错题库、AI 整理、反思和报告。
- 笔记工作区：生成、排版和保存复习图片。
- 系统层：设置、鉴权、备份恢复和第三方连接。

前端以流畅版 `index.html` 为主，服务根入口 `/` 固定指向该页面；封存的 `studio.html` 不作为线上根入口。服务端负责静态文件、JSON API、AI 代理、鉴权与磁盘持久化。

## 数据模型

当前主状态格式为 v6，顶层包含：

| 字段 | 含义 |
| --- | --- |
| `version` | 状态架构版本 |
| `profile` | 个人学习配置 |
| `dailyTasks` | 每日任务 |
| `tasks` | 背诵/复习任务 |
| `wrongQuestions` | 错题条目 |
| `plans` | 阶段规划 |
| `reflections` | 反思记录 |
| `reports` | 阶段报告 |
| `englishReading` | 英语阅读篇目、多次作答、原文选区、查询历史和多语境义词库 |
| `updatedAt` | 最近更新时间 |
| `migrations` | 数据迁移标记 |

`data/state.json` 是当前事实来源；`data/backups/` 保存历史快照；`data/generated-notes/` 保存图片产物。运行时设备信任、集成会话、后台队列和下载缓存不是学习档案。

`englishReading` 自身版本为 6，包含 `passages[]`、`lexicalEntries[]`、`lookupHistory[]` 和 `dismissedLegacyHintKeys[]`。每篇由年份与 Text 1–4 定位，保存原文、选区标记和多次作答；分数不存储，而是按每道错题扣 2 分实时推导。单词以小写词元聚合，短语以规范化空格和小写文本聚合；同一表达可以有多个语境义，每个语境义独立保存挖空锚点、来源、阶段、到期日期和复习历史。

精读工作区仅处理用户主动点选的单词或框选的连续短语。即时查询与篇后批量解释都调用 `/api/ai/explain-reading-selections`，默认返回语境义、规范化表达、词性/类型、核心搭配和判断依据；拆句/辨析为单选区按需深度调用。用户选择“认识”只累计查询，“模糊”进入 3 天阶段，“不会”次日复习。相同表达第 3 次查询时提示，但不自动收录。

## AI 与第三方集成

文本和图像能力均通过服务端调用兼容 OpenAI 接口的提供商，可配置主提供商和备用提供商。英语阅读只解释用户主动提交的选区；未配置或调用失败时保留标记，不写入残缺词条。API key 仅保存在 `.env`，不会进入主状态文件。第三方错题服务的登录状态存放在独立本地文件，下载资源放入运行缓存；二者均被 Git 忽略。

AI 输出是辅助材料，可能存在事实、识别或排版错误，用户需要在写入学习档案前复核。错题原文和个人记录发送给外部提供商时，应同时遵守相应服务的隐私条款。

## 部署架构

```text
浏览器
  │ HTTP(S)
  ▼
Nginx / VPN / 外围身份认证（推荐）
  │
  ▼
Node.js server.js
  ├── 静态页面与图片
  ├── 学习状态与备份
  ├── 写接口 token 校验
  └── 文本/图像 AI 与第三方服务代理
```

应用运行时不依赖数据库或 npm 第三方包。持久化依赖服务目录的可写文件系统，适合本机或单实例服务器。

## 安全边界

- 未配置 `ACCESS_TOKEN` 时服务保持只读；空 token 永远不能获取写权限。
- 已配置 token 后，正确 token 或已登记可信设备可执行写操作。
- 读取学习状态和静态图片不要求应用 token，因此公网部署必须增加外围访问控制。
- `.env`、可信设备、集成 access token、后台队列、缓存和日志不进入仓库。
- 私有仓库降低误公开风险，但不等同于加密存储；有仓库访问权的人可读取全部学习档案。
- 当前不支持多用户隔离、权限分级、密钥轮换、服务端加密或完整审计。

## 当前数据快照

状态格式为 v6。线上部署由流畅版 v4 直接执行幂等迁移，只增加空的 `englishReading` 和迁移标记，不重排或合并既有每日任务、错题、规划及 45 天进度。仓库内 `data/state.json` 仅是个人归档快照，线上实时数据以部署目录中的状态文件为准。

初始归档提交 `510b650` 保留了历史状态备份和生成笔记图片；需要时仍可从该提交恢复。以上内容均是个人学习数据，以明文保存在私有 Git 仓库历史中。

## 已知限制

- 单实例文件写入模型，不适合并发部署或多节点共享。
- 无数据库事务、跨设备冲突合并和结构化导入导出向导。
- 前端主要为大型单文件，后续维护和自动测试成本较高。
- 应用 token 只控制写入，不保护读取内容。
- AI 与第三方服务的可用性、费用和数据处理规则由各提供商决定。
- 大量二进制图片和历史 JSON 会持续增加 Git 仓库体积。

## 路线图

1. 为状态迁移、鉴权和恢复流程补充自动化测试。
2. 增加加密导出、完整性校验和更清晰的恢复向导。
3. 将只读访问纳入可配置身份认证，减少公网暴露面。
4. 拆分前端模块并建立稳定的数据 schema 校验。
5. 增加复习间隔建议、数据趋势和跨设备冲突处理。

本档案记录当前 Beta 阶段，不承诺公开发布或开源；仓库不附加开源许可证。
